# 패턴이 실제로 봉제되는지 검증하고 고치기

도면이 그럴듯해 보이는 것과 봉제되는 것은 다르다. 이 스킬은 **눈으로는 안 보이는**
불일치를 숫자로 잡아내고 고치는 방법이다.


## 0. 정답지가 없으면 **정답지부터 만든다** (가장 먼저 할 일)

> 「제공된 자료와 네가 그린 출력물을 비교·검증하는 일이 너무 많다. 전부 네가
> 검증 단계에서 걸렀어야 하는 일이다.」 — 사용자, 2026-08-14

맞는 말이다. DXF 정답지가 없는 모듈에서 결함 12건을 **전부 사용자가 눈으로** 잡았다.
원인은 하나다 — **길이·거리 같은 스칼라만 검사했고, 좌표를 대조하지 않았다.**
스칼라 검사는 거울·회전·모양 변화에 **불변**이라 조각이 뒤집혀도 통과한다.

### 도면 이미지가 있으면 그게 곧 정답지다

`tools/도면-좌표찍기.html` (단일 HTML · 서버 없이 동작)

1. 도면 이미지를 연다
2. **보정점**을 3개 이상 클릭하고 그 **제도 좌표**를 적는다 → 축척·회전·**거울**이 자동으로 풀린다
3. **번호점**을 클릭한다 (번호를 물어본다)
4. 곡선은 5~8점씩 찍는다 → 하우스도르프 비교용
5. `docs/answer/<모듈>-<조각>.json` 으로 저장

```json
{ "transform": {"scale_px_per_cm": 17.3, "rotation_deg": -90,
                "mirrored": true, "residual_cm": 0.08},
  "points": {"12":[23.0,21.0], "42":[17.14,11.5]},
  "curves": {"bArm":[[19.0,2.5],[18.2,6.1],…]} }
```

**클릭 20분 → 이후 세션 내내 자동 대조.** 번호점 30개면 이번에 놓친 12건 중 8건이
첫 실행에서 잡힌다. 눈대중 픽셀 계측(라벨 위치 ≠ 점 위치)도 사라진다.

### ⚠ 보정점은 **삼각형**을 이루어야 한다

일직선 위의 점만 찍으면(예: 앞중심선 위의 2·3·6번) **정상/거울 잔차가 둘 다 0** 이라
한쪽을 고를 수 없다. 조각이 통째로 뒤집힌 채 「잔차 0」으로 통과한다.

```
보정점            거울 감지   정상잔차 / 거울잔차   12번 복원
일직선 (2·3·6)     ✗          0.00 / 0.00         −23  ← 틀림
삼각형 (2·3·12)    ✓          25.93 / 0.00         23  ✓
```

도구가 **삼각형 지수**(넓이 / 최대변²)를 재서 0.02 미만이면 경고한다.
중심선에서 떨어진 점(겨드랑·어깨끝)을 반드시 하나 넣을 것.

### ⚠ 도면이 **비균등하게 늘어나 있을 수 있다**

원피스 뒤판이 그랬다 — 열 간격으로 잰 축척 **23.3 px/cm** 와 뒤중심선으로 잰
**28.7 px/cm** 가 23% 달랐다. 닮음변환(축척 하나)으로는 절대 안 맞고,
억지로 맞추면 **틀린 정답지**가 나온다 — 지금보다 나쁘다.

도구에 **어파인**(가로·세로 축척이 달라도 됨) 모형을 넣었다. 두 모형의 잔차를
나란히 보여 주므로, 닮음이 안 맞고 어파인만 맞으면 늘어난 도면이라는 뜻이다.
⚠ 어파인은 **점 4개 이상**이라야 한다 — 3개면 미지수 6 = 식 6 이라 항상 잔차 0(과적합).

**픽셀로 점을 자동 식별하려 들지 말 것.** 직선(투영으로 ±1px)은 확실하지만
「어느 교점이 몇 번인가」는 확정이 안 된다. 실제로 시도했다가 서로 모순되는
축척 두 개를 얻었다. 직선 검출로 **클릭할 자리를 좁혀 주고**, 번호는 사람이 찍는다.

### ⚠ 원점·축척은 **비율**로 확정한다 (치수로 하면 순환논법)

「이 세로선이 기준선이겠지」로 시작하면 축척이 그 가정에 오염되고, 그 축척으로 잰
값이 다시 가정을 뒷받침한다. 원피스 앞판에서 이걸로 여러 번 헛돌았다.

**축척에 무관한 비율을 만들어 후보를 가른다.** 예: 진동깊이/목너비 는 모든 호수에서
정확히 3.000 이다.

```
기준선 후보   BL/목너비   판정
px 1832       2.674      ✗
px 1892       3.011      ✓  ← 이것만 엔진과 맞는다
```

원점이 정해진 다음에야 축척을 재고, 그 축척으로 다른 값을 검증한다.
**여러 랜드마크가 하나의 축척으로 모이는지**가 최종 확인이다 — 흩어지면
원점이 틀렸거나 랜드마크를 잘못 짚은 것이다(원피스: 25.5/23.9/23.9 → 22.8/22.4/22.9).

### ⚠ 라벨 위치로 좌표를 추정하지 말 것 — **선을 피팅**하라

번호 라벨은 점에서 떨어져 찍힌다. 라벨로 어림한 값은 1~3cm 씩 틀렸다.
선은 **강건 반복 피팅**으로 뽑는다 — 대략의 직선을 놓고, 그 주변 ±7px 의
화소만 모아 최소자승, 다시 그 선 주변으로 모으기를 5~6회.

```
방법                              결과
색으로 범위 훑어 한 번에 피팅       RMS 39 px   ← 다른 선이 섞였다
강건 반복 피팅 (±7px, 6회)         RMS 0.5 px, 245점  ✓
```

가로선(검정 격자)과 겹치는 구간은 제외해야 한다 — 색 판정이 그 자리에서 끊긴다.

**곡선 길이는 열 단위 추적이 아니라 화소 위 최단경로(다익스트라)로.** 암홀은 끝에서
거의 세로가 되어 열 단위 추적이 끊긴다. 색 마스크에 다익스트라를 돌리고
**부모 포인터로 역추적**하면 시작점→끝점 순서까지 그대로 나온다.

### ⚠⚠ 원시 경로 길이는 **7% 부푼다** — 반드시 솎고 재라

8방향 격자를 따라가면 굵은 선(3~5px) 안에서 지그재그가 생긴다. 이걸 모르고 재면
**결론의 부호가 뒤집힌다.** 원피스에서 실제로 그랬다 — 「AH 가 모자라다」로 세 번을
파고들었는데, 바로잡으니 **엔진이 도면보다 길었다**.

`0.12cm 간격으로 솎으면` 정확히 걷힌다. **길이를 아는 직선으로 반드시 교정할 것**:

| | 원시 | 0.12 솎기 | 0.30 솎기 | 실제 |
|---|---|---|---|---|
| 직선(어깨선) | 12.693 | 11.830 | 11.788 | **11.773** |
| 오차 | +7.8% | +0.48% | +0.13% | — |

교정 없이 추출한 길이는 쓰지 말 것. 도면에 길이를 아는 직선은 항상 하나쯤 있다
(어깨선·품선·기준선).

### 곡선의 시작점을 **한 점 옆으로** 잘못 잡으면 길이가 통째로 틀린다

원피스 뒤 암홀은 **22번이 아니라 23번**에서 시작한다(어깨 다트분만큼 바깥).
22 에 씨앗을 놓으면 다익스트라가 어깨선을 1.5cm 타고 와서 그만큼 길게 나온다.
**엔진 코드에서 곡선을 만드는 실제 인자**를 보고 씨앗을 정하라 — 도면 라벨이 아니라.

### 끝단 0.5cm 는 접선 측정에서 버려라

곡선의 양 끝은 이웃 선(어깨선·옆선)과 만나는 자리라 색이 섞인다. 원피스 뒤 암홀의
시작 접선이 0~0.4cm 구간에서 21.8° 로 나왔지만(어깨선 오염) 0.8~1.8cm 에서는
103° 로 규칙값 110.7° 를 향해 수렴했다. **여러 기준거리로 재서 수렴을 보라.**

### ⚠ 나란한 두 줄을 하나로 착각하지 말 것

원피스 앞판 도면에 세로선이 **2.60cm(=유차) 간격**으로 두 줄 있었다
(47번 = 앞 진동선, 12번 = 뒤 진동선). 47 을 12 로 읽으면 「앞 진동선이 유차만큼
틀렸다」는 그럴듯하고 완전히 틀린 결론이 나온다. 검출된 선 사이 간격이
**제도 상수와 같으면**(유차·다트분·이세) 두 줄일 가능성을 먼저 의심한다.

### 겹쳐 찍힌 라벨은 **단서**다

원피스 도면에서 56 과 57 라벨이 서로 겹쳐 있었다 = 두 점이 같은 자리라는 뜻.
원문 문장대로 읽으면 3cm 떨어져야 해서 절대 겹칠 수 없었고, 그게 원문 해석이
틀렸다는 신호였다. 라벨이 몰려 있으면 왜 몰렸는지 설명할 수 있어야 한다.

### 겹쳐 보기로 즉시 확인

엔진 출력 `{"12":[23,21], …}` 을 도구에 붙여넣으면 도면 위에 빨강으로 겹치고
**같은 번호끼리 연결선과 Δ오차**를 표시한다. 0.15 를 넘으면 행이 붉어진다.
「어디가 틀렸나」를 말로 설명할 필요가 없어진다.

### 순서를 뒤집는다 — **검사 먼저**

원문을 전사한 직후, **엔진을 쓰기 전에** 정답지와 검산기를 만든다.
그러면 엔진은 「검사를 통과시키는 것」이 되고, 지금처럼 「엔진을 짠 뒤 검사를 발명」하지
않는다. 발명하는 순간 **빠뜨린다** — 원문 [40]·[15]·[5] 가 그렇게 빠졌다.

### 전사할 때 검사식을 **같이** 적는다

제도법 doc 을 산문으로만 쓰면 사람이 검사로 옮겨야 하고, 옮기다 빠진다.
단계마다 한 줄씩 붙인다:

```yaml
- step: "[19]"  rule: "32번에서 다트분 나가서 33번"  check: dist(32,33) == K.backDart
- step: "[40]"  rule: "71번에서 0.3 나간 곳"        check: offset(fPrinOut, 58→70, 1/3) == +0.3
- step: "[5]"   rule: "6번에서 1.5 앞 = 9번"        check: p9.x - p6.x == 1.5
```

### 회귀 코퍼스

잡은 결함마다 **재현하는 최소 diff** 를 남긴다. 새 검사를 넣을 때마다
「지금까지의 N 건이 다 잡히나」를 한 번에 돌린다 — 손으로 하나씩 깨뜨려 보는 것보다 확실하다.

## 소매 이세는 겨드랑에 넣지 않는다

맞물리는 두 변의 **길이**만 보면 놓친다 — 이세를 **어디에** 넣었는지도 봐야 한다.

암홀 너치를 몸판·소매 각각 "길이의 1/3·2/3" 로 찍으면 이세가 세 구간에 균등하게
들어간다. 겨드랑 쪽은 곡률이 세서 그러면 **주름이 잡히고 겨드랑이 당긴다.**

- **겨드랑 구간 이세 = 0** (몸판과 소매 길이가 같아야 한다)
- 남은 이세는 위 두 구간에 균등 — **0 : 50% : 50%**
- 전체 이세는 **뒤 60% / 앞 40%**. 제도 그대로면 보통 앞이 더 많으므로
  **어깨 맞춤 너치를 소매산 위에서 옮겨** 맞춘다 (정점은 제도점이라 그대로 둔다)
- 소매산 너치 = 몸판 구간 길이 누적 + 그 구간까지의 이세 몫

검사: 구간별 (소매 − 몸판) 이 배분값과 ±0.06, **겨드랑 구간은 |이세| ≤ 0.03**.

## 첫 번째 원칙: 봉제되는 두 변은 길이가 같아야 한다

쓸모 있는 검사는 대부분 이 형태다. 조각 A의 어떤 변과 조각 B의 어떤 변이 서로 꿰매진다면
**두 길이가 같아야 하고**, 다르면 그 차이만큼 한쪽이 남는다. 실측해서 숫자로 보고한다.

| 무엇 | 무엇과 |
|---|---|
| 소매산 | 암홀 + 오그림 |
| 큰소매 앞솔기 | 작은소매 앞솔기 |
| 안감 솔기 | 안감 상대 솔기 (밑단 올린 뒤에도) |
| 소매 래글런선 | 몸판 래글런선 |
| 칼라 목선 | 뒤목 + 앞목(고지점→SNP) |
| 칼라 고지선 | 라펠 고지선 |
| 후드 목선 × 2 | 몸판 넥라인 |

면적·각도·비율 같은 검사는 보조다. **먼저 길이를 재라.**

### 재는 대상은 `calc*()` 가 아니라 **`P` 에 실린 패스**다

제도값과 도면에 나간 선은 다를 수 있다. 칼라를 제도값(뒤목 9.026)으로 잡았는데
몸판은 `splitPanel` 을 거쳐 9.275 로 그려져 0.25cm 짧았다 — 제도값끼리 비교했으면
영영 안 잡혔다. **공장에 나가는 건 패스지 제도값이 아니다.**

```js
// 이렇게 말고
ok(collar.BNL === bodice.backNeckLen);
// 이렇게
const drawn = g.P.filter(p => p.seam === 'neck').map(p => sampleD(p.d, 0.02));
ok(Math.abs(len(drawn) - collar.BNL) < 0.03);
```

## 두 번째 원칙: 그려진 것과 잘리는 것은 다르다

이 세션에서 세 번 나왔다. 선이 화면에 있어도 조각의 **테두리**가 아니면 DXF에 없다.

- 래글런선이 `cls:'consd'` 오버레이 → 몸판은 어깨+진동을 그대로 가진 채 잘렸다
- 라펠 윤곽이 `cls:'solid'` + seam 태그 없음 → 앞판이 **민목**으로 잘렸다
- 그래서 상칼라의 고지선은 맞물릴 상대가 아예 없었다

**탐지법**: 폐곡선을 만들고 태그를 찍어 본다.
```js
chainSeamLoops(part.P).forEach(l => console.log([...new Set(l.tags)]));
part.P.filter(p => p.cls === 'solid' && !p.seam)   // ← 오버레이. 비어 있어야 정상
```
회귀 검사로 박아둘 것: `seam 없는 solid 패스가 남으면 실패`.

## 작업 순서

0. **정답지부터.** DXF 가 없으면 `tools/도면-좌표찍기.html` 로 도면에서 번호점을 찍어
   `docs/answer/*.json` 을 만든다 (§0). 이게 있으면 아래 대부분이 자동이다.
0-1. **그려서 원본과 대조.** 렌더 PNG 를 원본 도면과 나란히 본다 (네 번째 원칙).
1. **실측부터.** 고치기 전에 잰다. 사용자가 "합인 넣어줘" 라고 해도, 맞물릴 두 변의
   길이가 다르면 합인을 놓을 자리가 없다 — 그걸 먼저 숫자로 보고한다.
2. **모순은 숫자로.** "88호에서 1.71cm 모자람, 호수 따라 커짐" 처럼. 추측하지 말고 잰다.
3. **고치고 다시 잰다.** 첫 수정이 다른 걸 깨는 일이 흔하다(아래 함정표).
4. **회귀 검사를 넣는다.** 느슨한 부등호 말고 **정확한 값**으로. 그래야 나중에 깨지면 걸린다.
5. **커밋.** 무엇이 왜 틀렸는지, 숫자와 함께.

## 곡선 길이를 목표에 맞출 때는 이분법

반복해서 필요했다. 끝점 x 를 「길이」로 그냥 쓰면 곡선이라 실제가 더 나온다.

```js
const at = (x) => [[0,0],[x*0.55,-0.3],[x,-1.2]];
let lo = target*0.5, hi = target*1.2;
for (let i=0;i<48;i++){ const m=(lo+hi)/2; if (curveLength(at(m)) < target) lo=m; else hi=m; }
```
같은 방법으로: 후드 깊이(곡선의 실제 최전방), 안감 소매 캡 높이, 겨드랑이 이음의
**호길이 보존** 블렌드, 래글런선 목점 높이.

## 세 번째 원칙: 곡선은 **곡률까지** 이어져야 한다

편차가 작아도 사람 눈에는 꺾여 보일 수 있다. 반드시 따로 잰다.

```js
// 곡률 급변 최대치 — 0.15 이하여야 매끄럽게 보인다
function maxCurvatureJump(poly){const ang=[],k=[];
 for(let i=1;i<poly.length;i++)ang.push(Math.atan2(poly[i][1]-poly[i-1][1],poly[i][0]-poly[i-1][0]));
 for(let i=1;i<ang.length;i++){let d=ang[i]-ang[i-1];while(d>Math.PI)d-=2*Math.PI;while(d<-Math.PI)d+=2*Math.PI;
  const ds=Math.hypot(poly[i+1][0]-poly[i][0],poly[i+1][1]-poly[i][1]);k.push(ds>1e-9?d/ds:0);}
 let j=0;for(let i=1;i<k.length;i++)j=Math.max(j,Math.abs(k[i]-k[i-1]));return j;}
```

- **원인은 거의 항상** 앵커 사이를 큐빅 하나씩 만들고 구간별 장력을 따로 준 것이다.
  접선만 이어지고(G1) 곡률이 안 이어진다. → **C2 연속 스플라인**으로 바꾼다
  (`pattern-draft-app` 스킬의 `splineSegs`).
- 실사고: 앞 암홀 곡률이 −10.2 ↔ +11.0 으로 뒤집혀 급변 17.5. C2 로 바꾸니 0.011.

### 도면 대조 편차는 반드시 **양방향**으로

한 방향(도면 점 → 내 곡선)만 재면 **내 곡선이 밖으로 튀거나 고리를 만들어도 편차가 안 는다.**
실사고: 뒷목둘레가 편차 0.038 "합격"인데 곡선길이는 13.23(도면 8.91)이었다 — 고리가 있었다.

곡선 검증은 네 가지를 **전부** 본다:

| 항목 | 기준 |
|---|---|
| 편차 (하우스도르프, 양방향) | ≤ 0.05~0.10 |
| **곡률 급변** | ≤ 0.15 |
| **자기교차** | 0 |
| **곡선길이 vs 도면** | ±0.10 |
| **끝접선** (어깨점) | 어깨선 수직 ±0.5° |

### 끝접선 — 도면보다 봉제 규칙이 우선

목선·암홀이 어깨점에서 어깨선에 **수직으로** 도착하지 않으면 앞뒤를 어깨에서 봉제했을 때
목선·암홀이 꺾인다. 원본 도면은 3~13° 벗어나 있는 경우가 흔하다 — **규칙을 따르고**
끝점 근처의 도면 편차는 허용치로 받는다. 적합 파라미터에 끝접선 회전을 넣으면 적합기가
도면을 따라가며 규칙을 깨뜨리므로 **넣지 않는다**.

⚠ `selfIntersections()` 가 폐곡선용이면 **열린 곡선에서 헛걸린다**(마지막↔첫 점을 이음).

## 네 번째 원칙: **길이가 맞아도 모양은 틀릴 수 있다**

> 「길이만 보고 이미지와 대조 안 하면 무슨 의미가 있나?」 — 사용자, 2026-08-14

봉제 검사(길이 짝·둘레·이세)는 전부 **스칼라 하나**다. 스칼라는 모양을 구속하지 못한다.
정답지 DXF 가 없는 모듈에서 이걸 잊고 두 번 연속으로 잘못된 곡선을 내보냈다.

| 실사고 | 길이 검사 | 실제 |
|---|---|---|
| 원피스 소매산 | 이세 1.83 ✓ · 소매통 33.5 ✓ | 정수리가 평평하고 뒤쪽에 각 |
| 원피스 앞목 | 목둘레 ✓ | 목옆점 앞에서 **되돌아 나감**(총회전 201° · 곡률 3.19) |
| 원피스 뒤암홀 | 암홀↔등품선 1.02 ✓ | 접점 부근이 곧은 세로 구간 + 양 끝 꺾임 |

### 반드시 두 가지를 **같이** 한다

**① 그려서 원본 이미지와 나란히 놓고 본다.** 이게 빠지면 나머지는 의미가 없다.

```bash
node -e "…draft() → JSON…" && python3 render.py && qlmanage -t -s 1500 -o . out.svg
```
그리고 **렌더 PNG 를 실제로 읽어서** 원본 도면 사진과 비교한다. 특히
겨드랑 훅 · 소매산 정수리 · 목옆점 · 어깨 끝 — 각이 지는 곳은 늘 같다.

**② 모양 불변량을 검산기에 박는다.** 눈은 다음 세션에 없다. 숫자는 남는다.

```js
function shapeOf(segs) {            // 0.05 간격 표본 → 곡률
  const p = sampleSegs(segs, 0.05), ang = [], ds = [];
  for (let i=1;i<p.length;i++){const d=[p[i][0]-p[i-1][0],p[i][1]-p[i-1][1]];
    ang.push(Math.atan2(d[1],d[0])); ds.push(Math.hypot(d[0],d[1]));}
  const k=[]; let turn=0;
  for (let i=1;i<ang.length;i++){let da=ang[i]-ang[i-1];
    while(da>Math.PI)da-=2*Math.PI; while(da<-Math.PI)da+=2*Math.PI;
    k.push(da/(((ds[i]+ds[i-1])/2)||1e-9)); turn+=Math.abs(da);}
  const sm=[],W=6; let mx=0;                       // 창 6 으로 민다 — 안 밀면 끝점마다 가짜 변곡
  for(let i=0;i<k.length;i++){let a=0,c=0;
    for(let j=Math.max(0,i-W);j<Math.min(k.length,i+W+1);j++){a+=k[j];c++;}
    sm.push(a/c); mx=Math.max(mx,Math.abs(a/c));}
  const lim=Math.max(0.08,mx*0.10); let infl=0,prev=0;   // 반지름 12cm 보다 평평하면 직선 취급
  sm.forEach(v=>{const sg=v>lim?1:(v<-lim?-1:0); if(sg&&prev&&sg!==prev)infl++; if(sg)prev=sg;});
  const deg=r=>r*180/Math.PI;
  return {maxK:mx, infl, turn:deg(turn), t0:deg(ang[0]), t1:deg(ang.at(-1))};
}
```

| 재는 것 | 뜻 | 기준 |
|---|---|---|
| `maxK` | 최대곡률 = **각** | 암홀·소매산 ≤ 0.6 · 목선 ≤ 0.7 (1/maxK 가 반지름 cm) |
| `infl` | 변곡 횟수 = **물결** | 암홀 ≤ 1 · 소매산 ≤ 1 · 목선 ≤ 2 |
| `turn` | 총회전 | 목선 ~95° · 암홀 ~113° — 크게 넘으면 되돌아 나간 것 |
| `t0`·`t1` | 끝접선 | 어깨 끝·목옆점 = 어깨선 ⊥ · 겨드랑·소매통 = 수평 |

`turn` 이 가장 잘 잡는다 — 고리·되돌아감은 곡률 스파이크 없이도 회전각을 부풀린다.

### 회귀 검사는 **일부러 깨뜨려 확인한다**

넣자마자 옛 코드를 되돌려 넣어 **✗ 가 뜨는지** 본다. 안 뜨면 그 검사는 장식이다.
(앞목 끝접선을 옛 값으로 되돌리니 `곡률 3.34 > 0.7`·`끝접선 89.1° (기대 −67.1°)` 로 잡혔다.)

### ⚠ 결함을 고치면 **엉뚱한 검사가 걸린다** — 문턱부터 의심하라

결함이 남아 있는 상태에서 관측값에 맞춰 잡은 문턱은, 결함을 고치는 순간 실패로
바뀐다. 이때 새 코드를 되돌리면 안 된다 — **문턱을 뭘 보고 정했는지** 먼저 캔다.

원피스 실사고: 앞 어깨를 도면대로 고치자 「소매산 앞뒤 기울기 차 ≥ 8°」가
66·77·88호에서 걸렸다. 골격 도면을 다시 재 보니

- 뒤 대각선은 9번이 아니라 **6번**으로 간다 → 검사가 **잰 대상**부터 틀렸다
- 도면 실측은 앞 46.8° 뒤 41.3° **차 5.53°** — 8° 는 애초에 없는 값이었다

즉 새 결함이 아니라 **묵은 검사 결함이 드러난 것**이었다. 판별법:

| 신호 | 뜻 |
|---|---|
| 문턱이 도면이 아니라 **그때 나온 값**에서 왔다 | 검사가 틀렸다 |
| 고친 쪽이 도면과 더 가까워졌다 | 검사가 틀렸다 |
| 일부 호수만 걸린다 | 문턱이 경계에 걸쳐 있었다 = 근거가 약했다 |

고칠 때는 문턱만 늘리지 말고 **도면에서 잰 값과 그 픽셀 근거를 주석에 남긴다.**
가능하면 각도 하나가 아니라 **비율 여러 개**로 바꾼다 — 원피스는 반너비 비율
3종을 추가했고, 옛 코드를 되돌리니 5가지로 걸렸다.

### 기대값에 **상수(K)를 쓰지 않는다** — 자기만족 검사

검사가 `engine.K.foo` 를 기대값으로 쓰면, **K 를 고칠 때 기대값도 같이 움직인다.**
그 검사는 영원히 통과한다. 한 세션에 이 함정을 두 번 밟았다:

| 실사고 | 무슨 일이 |
|---|---|
| 재킷 단추 위치 | `K.overlap` 을 도면값 7.89 와 비교 — K 가 곧 7.89 라 항상 ✓ |
| 원피스 앞 절개선 | `K.frontPrinOut` 을 0.3 → **0 으로 되돌렸는데 45/45 그대로** |

**규칙**

- 교본이 **하나로 못 박은 값** → 검사에 **리터럴**로 적는다
  (`1.5` · `4.8` · `0.5` · `0.3` · `B/12 + 0.5` …)
- 교본이 **폭을 준 값**(「2~2.5」·「0.3~0.5」) → K 를 쓰되,
  **그 K 가 범위 안인지** 별도 항목으로 검사한다

```js
// 값 자체가 교본 범위 안인가 — 좌표 검사와 따로 둔다
[['backDart', K.backDart, 2.0, 2.5], ['frontPrinOut', K.frontPrinOut, 0.3, 0.3], …]
  .forEach(([n, v, lo, hi]) => { if (v < lo || v > hi) bad.push(`K.${n} = ${v} — 교본은 ${lo}~${hi}`) })
// 좌표는 리터럴로
if (dist(p54, [B/12, 1.0]) > 0.02) bad.push('54번이 식과 다르다')   // K.neckDrop1 아님
```

그리고 **깨뜨려 확인**한다. 리터럴로 바꾼 뒤 `frontPrinOut 0.3→0` 을 다시 넣으니
`K 범위 위반` + `[40] 71번 편차 0.000` 두 항목이 잡혔다 — 그제야 검사다.

같은 이유로 **엔진이 내보내는 값끼리 비교하지 않는다.** 「앞 솔기 == 뒤 솔기」처럼
작도상 반드시 같아지는 쌍은 통과해도 아무 정보가 없다 — 그게 왜 같은지(가로 span 이
둘 다 `Lrest/2`) 먼저 손으로 확인하고, 검사는 **교본이 요구한 값**에 건다.

### 원문 텍스트가 애매하면 **이미 검증된 작도**를 쓴다

「5번에서 4.5 나가서 15번」처럼 방향이 안 적힌 문장을 추측해서 스플라인 통과점으로 꿰면
길이는 맞고 모양이 틀린다. 리포에 정답지로 맞춰 둔 작도(`capGeom` 같은)가 있으면
**그것을 쓰고**, 원문 점들은 **대조용 마크**로 남긴다. 골격(소매산 높이·대각선=암홀)이
같다면 곡선 규칙도 같은 것이 맞다.

## 다섯 번째 원칙: **교본이 시킨 대로 그렸는지**를 검사한다

> 「이미지로 준 제도법을 준수했나? QA팀은 이 제도법대로 그렸는지 검증했나?」
> — 사용자, 2026-08-14

교본 검산기를 만들 때 거의 항상 **숫자만** 옮긴다: 「어깨/2」, 「암홀↔등품선 1」,
「이세 1.5~2」, 「소맷부리 24」. 전부 스칼라라서 **모양이 틀려도 통과한다.**

교본 문장의 절반은 숫자가 아니라 **작도 지시**다:

- 「16번에 **곡자를 대고** 15번과 연결」
- 「41번이 **최대한 맞닿을 정도로**」
- 「29번을 **향하여**」 · 「78번과 **붙게**」
- 「44번에 곡자를 대고 밑단」

이건 전부 **곡선이 어느 점을 지나는가**로 잴 수 있다. 안 재면 안 지킨 채로 나간다.

```js
function nearest(segs, P) {                     // 곡선에서 점까지 최단거리
  let b = 1e9;
  for (const q of sampleSegs(segs, 0.02)) b = Math.min(b, dist(q, P));
  return b;
}
// [단계, 곡선, 지나야 할 점, 허용, 교본 문장]
[['[26]', bNeck,   p41, 0.25, '뒷목선이 41번에 맞닿는다'],
 ['[21]', bPrinIn, p29, 0.25, '절개선이 29번을 지난다'],
 ['[28]', bHem,    p43, 0.60, '밑단이 43번 근처(44번에 곡자)']]
```

| 교본 표현 | 허용 |
|---|---|
| 「지나간다 · 연결한다」 | 0.15 |
| 「맞닿을 정도로 · 붙게 · 향하여」 | 0.25 |
| 「곡자를 대고」(통과점이 아니라 자를 대는 자리) | 0.6 |
| 수치가 붙은 것(0.3~0.5 · 1) | 그 범위 |

그리고 **좌표로 못 박힌 점**은 식 그대로인지 따로 본다
(`9번 = 6번에서 1.5 앞`, `앞목 깊이 = B/12 + 0.5`).

보고는 **「원문 점 통과 11/15」** 처럼 분수로 한다. 「전체 통과」라고 쓰면
검사에 없는 항목이 몇 개인지 아무도 모른다.

### 숫자를 맞추려고 **모양을 버리지 않는다**

교본 조건이 안 나올 때 파라미터를 밀어 억지로 맞추면, 맞는 순간 곡선이 무너진다.

실사고 — 교본 [15] 「뒤 솔기 = 앞 솔기 + 0.5(이세분)」이 실제로는 0.000 이었다.
뒤 솔기를 부풀려 0.5 를 만들 수는 있었지만 **휨이 0.35 → 3.07** 로 뛰어 도면과
완전히 달라졌다. → 고치지 않고 **경고로 계속 띄우고**, 관련 번호점(22·23·24)을
다시 읽어야 한다고 코드 주석과 보고에 남겼다.

같은 이유로 **먼 자유단에서 길이를 갚지 말 것**: 어깨~겨드랑 21cm 구간에서 생긴
0.3 차이를 100cm 짜리 절개선 밑단 끝점을 밀어 맞췄더니 밑단이 2.5cm 나 밀리고
교본의 다른 조건(38·39 의 2등분 = 35번)까지 깨졌다.
**길이는 차이가 생긴 자리에서 갚는다.** 그럴 자리가 없으면 그건 이세다.

### 교본이 **자기 주석과 모순**할 때 — 그림보다 숫자

도면에 그려진 선과 같은 도면에 적힌 숫자가 안 맞을 수 있다. 실사고:

| | 도면에 그려진 곡선 | 같은 도면의 주석 |
|---|---|---|
| 소매산 이세 | 대각선에서 0.33~0.45 휨 → **이세 0.15** | 「앞·뒤 암홀 + **이세 1.5~2**」 |

대각선이 정의상 앞AH·뒤AH 이므로 둘 다 만족시킬 수 없다.
→ **숫자로 못 박힌 검산 조건을 따른다.** 그림은 설명용으로 얇게·좁게 그린 모식도일 수 있다.
(이세가 없으면 소매를 실제로 못 단다 — 봉제가 판정한다.)

**먼저 도면이 축척인지 확인한다.** 알고 있는 두 치수의 비를 도면 픽셀비와 맞춰 본다.
축척이 맞는데도 어긋나면 위 결론이고, 축척부터 안 맞으면 그림은 애초에 비례도다.

그리고 이때 **도면에서 잠그는 것은 「모양」이지 「크기」다**:
곡률 부호 프로파일 · 0 교차 위치 · 끝접선 · 꺾임 — 이건 모식도에서도 맞다.
크기는 교본의 숫자가 정한다.

### 곡선 결함 진단표 — 증상에서 원인으로

| 증상 | 원인 | 처방 |
|---|---|---|
| 소매산 정수리가 평평하고 한쪽이 각짐 | 교본 통과점을 그대로 스플라인에 꿴 것 | 정답지로 맞춘 작도(`capGeom`)를 쓰고 교본 점은 대조용 마크로 |
| 곡선 중간에 **곧은 세로 구간** + 양 끝 꺾임 | 두 도막을 접점에서 잇고 양쪽 접선을 같은 방향으로 묶음 | 교본대로 **한 줄기** C2 스플라인 |
| 곡선이 끝점 앞에서 **되돌아 나감** | 끝접선 방향이 진행 방향의 반대 | 끝접선은 규칙으로 정한다(목선·암홀 = 어깨선 ⊥) |
| 곡선이 거의 **직선** | 통과점을 현(弦) 위에 둠 | 현에서 **직각으로 띄운다**(교본의 「곡자를 대는 점」) |
| 좁아지는 솔기가 **S 로 휨** | 기운 선인데 끝접선을 세로 `[0,±1]` 로 묶음 | 끝접선을 **현 방향**으로 |
| 조각 두 개가 겹침 | 다트 다리가 다트 끝에서 **교차**하는데 교본이 선 그은 짝으로 갈랐다 | 경계는 **끝까지 안쪽에 남는 쪽**으로 |
| 조각이 안 닫힘(점 간격 1.7 등) | 다트 다리를 `y=길이` 에서 끊었는데 밑단은 곡선 | 다리를 **진짜 밑단선까지** 늘린다 |

### 끝접선은 **규칙**으로 정한다 (도면에서 눈으로 읽지 말 것)

90° 눕혀 찍힌 사진에서 접선 각도를 읽으려 하면 계속 틀린다. 봉제 규칙이 먼저다.

| 자리 | 접선 |
|---|---|
| 목옆점 · 어깨 끝 | 어깨선에 **직각** (앞뒤 둘 다 90° 라야 어깨를 꿰맸을 때 180° 로 이어진다) |
| 겨드랑 | 옆선에 직각 = 진동선과 나란히 |
| 소매산 정점 · 소매통 끝 | 둘 다 **수평** |
| 골선(앞·뒤중심) | 골선에 직각 (안 그러면 펼쳤을 때 뾰족해진다) |

## 단일 HTML 앱을 Node 에서 돌리기

`file://` 단일 HTML 은 import 가 막혀 검증기가 함수를 떼어내야 한다.
**이름을 손으로 나열하지 말 것** — 앱에 함수 하나 끼어들면 조용히 깨진다.
의존성을 따라가는 하네스를 쓴다(`tools/app_harness.mjs` 패턴, `references/pitfalls.md` 참고).

## 정직하게 가르기

보고할 때 **검증된 것**과 **가봉이 필요한 것**을 반드시 나눈다.

- 검증됨: 길이 일치, 폐곡선, 시접 방향, 자기교차 없음, 좌표 왕복
- 가봉 필요: 곡률(뒤통수·얼굴선), 꺾임 여유, 레이어링 여유 — 소재·착장에서 나오는 값

데이터에 없는 치수로는 검산할 수 없다고 말한다. 예: 두위·두장이 없으면 후드에 머리가
들어가는지 확인할 수 없다. 있으면 **하한만** 말할 수 있다 — 후드는 머리에 밀착하지 않아서
「천 둘레 = 머리 둘레」로 놓으면 틀린 결론이 나온다.
