# 완성 패턴 표기 점검표

곡선 모양이 맞아도 여기가 틀리면 「패턴이 이상하다」는 지적이 나온다.
전부 **사용자가 실제로 짚었던 것**이다 (2026-08-14~15 · 조끼 모듈).

## A. 조각 구성

- [ ] **UI 기본값 = 엔진 기본값**인가. 엔진은 4조각인데 화면은 2조각으로 열리면
      사용자는 늘 다른 것을 본다. 「절개선이 그려진 형태면 4조각이어야 한다」
- [ ] 조각 이름이 사용자의 말과 같은가 (앞판·앞옆판·뒤판·뒤옆판)
- [ ] **안단도 조각으로 떠냈는가.** 안단선은 「제도 후 잘라 내는 선」이다 —
      본판은 그대로 두고 별개 조각(좌우 2매)으로 낸다
- [ ] 통짜 모드에도 절개선·다트가 **제도선으로** 보이는가 (교재는 통짜 위에 그린다)

## B. 선

- [ ] **기준선(진동선·허리선·앞품선·S~N 안내선…)이 조각 안에만 있는가.**
      조각 밖 허공에 뜬 선은 즉시 눈에 띈다. 조각별로 고르지 말고 **한 번에 클리핑**하라 —
      조각 구성이 바뀔 때마다 틀어진다
- [ ] 클리핑은 **기준선만**. 다트·BP 십자 같은 표시선을 자르면 뜻이 깨진다
      (폭 1.5 다트가 0.199 로 잘린 사고가 있었다)
- [ ] 선을 자르기 전에 **잘게 나눴는가**. 점 2개짜리 기준선은 「끝점이 밖」이라 통째로 사라진다
- [ ] 이어붙인 곡선이 **꺾이지 않는가**. 이음점의 접선을 앞 도막의 실제 끝접선으로 줘라
      (현 방향으로 주면 각이 진다)

## C. 너치

- [ ] **항상 재단선에 직각.** 방향만 안쪽으로 맞추면 선과 나란히 누워 묻힌다
- [ ] 조각 **꼭짓점**의 너치는 두 변의 **이등분선**으로 (한 변의 법선은 다른 변에 눕는다)
- [ ] 색이 재단선과 구분되는가 (검정 재단선 위의 검정 너치는 안 보인다 → 빨강)
- [ ] 짝이 있어야 하는 너치가 양쪽에 다 있는가 (한쪽에만 있으면 못 맞춘다)

## D. 다트 · 줄임 표시

- [ ] **접어 줄이는 표시(MP·이세)를 점으로만 찍지 않았는가.** 교재는 **선**으로 긋는다 —
      두 점에서 한 점으로 모이는 다트꼴
- [ ] MP 는 **접는 것이 아니다.** 「봉제할 때 박는 자리」다 — 곡선·조각을 건드리지 말고
      자리만 낸다. 이름이 「형지접어줄임」이라 오해하기 쉽다
- [ ] MP 자리가 앞뒤 **각자**인가 (앞은 목선, 뒤는 진동인 교재가 있다)
- [ ] 다트를 **회전해 절개선으로 넘길 때** 두 다리 길이가 같은가.
      다르면 접었을 때 삐져나온다 — 꼭짓점을 두 다리의 **수직이등분선** 위에 두라
- [ ] 다트 길이를 늘릴 때 **폭은 고정**인가 (「폭은 고정하고 길이만」)

## E. 밑단 · 안단

- [ ] **안단선인가 밑단인가.** 원문이 안단을 몇 개라고 하는지 세라.
      「어깨 4~5 · 앞단 6~7」 둘뿐인데 밑단 쪽 숫자(9·8·12·4.5)까지 안단으로 읽으면
      조각이 엉덩이선까지 내려간다 — 그 선이 **완성 밑단**이었다
- [ ] 제도 기준선(엉덩이선)까지 그린 뒤 **완성선에서 잘라냈는가**. 교재의 작업 순서다.
      제도(번호점)는 그대로 두고 조각만 자르면 번호점 검사가 살아 있다
- [ ] 자른 뒤 **시접이 새 밑단에 다시 붙었는가**
- [ ] 잘려 나간 자리의 표시(다트 끝·너치)를 지웠는가 — 조각 밖 허공에 남는다
- [ ] 안단선이 **목둘레선과 닮은꼴**인가. 「벌어짐은 달라도 형태는 비슷해야 한다」 —
      두 점 스플라인이 아니라 **목선을 밀어서(offset)** 만든다

## F. 검사기를 같이 옮겼는가 (제일 자주 나는 사고)

엔진을 고치고 검사를 안 옮기면 **멀쩡한 수정이 실패로 잡히거나, 틀린 것이 통과한다.**
한 번 고칠 때 아래를 전부 훑어라:

- [ ] 번호점 기대식 (§3) — 좌표식이 바뀌었으면 식도 바꾼다. 못 쓰면 성질 검사로 옮긴다
      (예: 「옆선 곡선 위의 점인가 · 호길이가 유차인가」)
- [ ] 조각 이름·개수표
- [ ] 필수 제도선표 / 필수 변(edge)표 — 표에 없는 선은 사라져도 아무도 모른다
- [ ] 너치 짝 목록
- [ ] 완성 치수 식 (밑단을 올렸으면 「완성 엉덩이」는 못 잰다 → 밑단 둘레로)
- [ ] 봉제 짝 허용치 (다트를 절개선으로 회전시키면 그쪽이 정상적으로 길어진다)
- [ ] UI 슬라이더 ↔ 엔진 상수 (죽은 상수는 슬라이더가 아무것도 안 움직인다)
- [ ] 정답지 tol 과 그 사유 주석

## G. 산출물이 오염되지 않았는가 (라벨·그림)

좌표는 멀쩡한데 **글자로 새는** 오류가 있다. 좌표 NaN 검사로는 절대 안 잡힌다.

- [ ] 조각의 **제도선 라벨·id · 너치 라벨 · 변 이름 · 조각 이름**에
      `undefined` / `NaN` / `[object` 가 없는가.
      라벨은 K 값을 문자열로 이어 붙여 만들기 때문에, 상수 이름이 바뀌면 계산은
      멀쩡한데 종이에 「안단선 어깨undefined」가 찍힌다
- [ ] **그림(SVG/PNG)도 산출물이다.** 겹침·확대 그림을 쓴 뒤 같은 글자를 세라 —
      그림 도구는 검산기가 안 보는 별도 코드라 오염이 조용히 나간다.
      실제로 겹침 도구가 사라진 상수를 읽어 「앞중심 undefined」와 NaN 30개를 찍었다
- [ ] ⚠ 그림 검사는 **base64 데이터를 빼고** 세라. 배경 도면이 data: URI 로 박혀 있으면
      그 난수열에 'NaN' 이 우연히 들어 있어 오탐이 난다 (넣자마자 그 검사부터 틀렸다)
- [ ] **인쇄 출력(print.js 가 만든 SVG)까지 세라.** 조각 라벨 검사는 엔진 산출물만 본다.
      종이에 찍히는 건 인쇄 코드가 따로 조립한 문자열이다 — 검사 없이 지나간다

### ⚠ `if (!x.anchor)` 류의 가드는 **문자열을 못 거른다**

JS 의 레거시 메서드 때문에 문자열이 온갖 속성 가드를 통과한다. 실제로 종이에
「undefined  undefined = 0」이 9장 찍혔다 (2026-08-18):

```js
'글자'.anchor      // → function  (String.prototype.anchor · 레거시)
!'글자'.anchor     // → false     ← 가드를 그냥 통과한다
'글자'.anchor[0]   // → undefined → * 10 → NaN → 좌표까지 오염
```

`link` `sub` `sup` `big` `bold` `fixed` `italics` `blink` `strike` `small` `fontcolor`
`fontsize` `at` `concat` `search` `match` 도 마찬가지다 — 제도 코드에서 쓰기 쉬운
이름이 많다. **모양을 통째로 확인하라**:

```js
function isDrawableNote(n) {
  return !!n && typeof n === 'object' && !Array.isArray(n) &&
         Array.isArray(n.anchor) && isFinite(n.anchor[0]) && isFinite(n.anchor[1]);
}
```

그리고 **문자열을 이어 붙일 때 없는 조각은 빼라** — `a + '  ' + b + ' = ' + v` 는
b 가 없으면 종이에 `undefined` 를 찍는다. 있는 것만 모아 `join` 하고, 결과가
빈 문자열이면 아예 그리지 않는다. 가드와 조립 **둘 다** 막아 두면 한쪽이 뚫려도
종이는 깨끗하다 (실제로 한쪽만 되돌렸더니 여전히 깨끗했다).

### 검사를 넣었으면 **오염을 주입해 증명하라**

이 프로젝트에서 「검사를 넣었는데 사실 헛돌더라」가 여러 번 있었다.
상수 이름을 일부러 깨뜨려 보고, 검사가 **잡는 것을 본 뒤** 원상복구한다.

```bash
# 예: K 이름을 깨뜨렸을 때 라벨 검사가 잡는가
sed -i '' "s/_fac('facingSh')/_fac('facingShXX')/" 모듈/engine.js
node suite-verify.js 모듈 | grep '라벨에'      # 잡혀야 한다
git checkout -- 모듈/engine.js
```

같은 방법으로 확인할 것: 너치를 지웠을 때 · 조각 이름을 바꿨을 때 ·
정답지 곡선을 흔들었을 때 검사가 **실제로 실패하는지**.
