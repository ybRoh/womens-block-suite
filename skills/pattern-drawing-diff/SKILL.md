# 도면 ↔ 완성 패턴 대조 (Drawing-vs-Pattern QA)

패턴 엔진이 **길이 검사는 다 통과하는데 모양이 교재와 다른** 상황을 다룬다.
길이·좌표 검사는 생김새를 못 잡는다. 여기서는 도면을 실제로 **재서** 대조한다.

## 0. 먼저 확인할 것

1. **엔진이 무엇을 그리는가** — `geom()`의 곡선 이름, `draft*()`의 조각·변 목록
2. **도면이 무엇을 그렸는가** — 완성이미지인지 제도 과정 이미지인지. 둘은 다르다
3. **원문(텍스트)이 뭐라고 하는가** — 도면과 충돌하면 §5의 우선순위로 판단

## 1. 측정 파이프라인

`references/pipeline.md`에 코드 수준으로 적어 두었다. 요약:

```
① 이미지를 BMP 로 변환 (sips -s format bmp)
② 색분류 — 앞판/뒤판/안단이 색으로 갈려 있으면 그대로 마스크가 된다
③ 축척 — 격자선·기준선 픽셀로 px/cm 와 원점을 세운다 (두 점 말고 3점 이상 최소제곱)
④ 엔진 곡선에 최근접 배정 → 국소 중앙값 2패스로 라벨·주석 픽셀 걸러내기
⑤ 0.12cm 데시메이션 → 정답지 JSON
⑥ 양방향 하우스도르프로 곡선별 편차 · 스캔라인 표로 높이별 x 비교
```

**축척을 두 점으로 세우지 마라.** 세 번째 점을 넣으면 0.1cm씩 어긋나는 게 보인다.

## 2. 대조를 끝내는 형식

곡선마다 이렇게 남긴다 — 숫자 없이 「비슷하다/다르다」로 끝내지 않는다.

| 곡선 | 엔진 | 도면 | 편차 | 판정 |
|---|---|---|---|---|
| 앞목선 | 직선 | 볼록 곡선 | 최대 1.9 | **엔진을 고친다** |
| 앞 절개 시작각 | 27° | 21° | y15 에서 1.0 | 도면을 안 따른다(시접 0.30 사수) |

판정은 셋 중 하나다:
- **엔진을 고친다** — 도면이 옳고 엔진이 틀렸다
- **도면을 안 따른다** — 봉제·원문이 이긴다. **사유를 코드 주석과 정답지 tol 에 남긴다**
- **사용자 결정** — 재단물이 바뀌는 선택 (다트 자리, 조각 구성 등)

## 3. 반드시 같이 보는 표기 규약

모양이 맞아도 이것들이 틀리면 「패턴이 이상하다」는 말이 나온다.
`references/checklist.md` 전체를 훑어라. 특히 자주 나오는 것:

- **제도선이 조각 밖 허공에 뜬다** — 기준선은 조각 안 구간만 남겨야 한다
- **너치가 재단선과 나란히 누워 안 보인다** — 항상 직각, 꼭짓점은 두 변의 이등분선
- **접어 줄이는 표시(MP·이세)를 점으로만 찍었다** — 교재는 선으로 긋는다
- **안단선을 밑단으로, 밑단을 안단선으로 읽었다** — 원문이 안단을 몇 개라고 하는지 세라
- **UI 기본값과 엔진 기본값이 다르다** — 화면에는 늘 다른 게 보인다

## 4. 고친 뒤 반드시

1. **정답지로 굳힌다** — `docs/answer/*.json` + 모듈 검산기의 대조 절.
   그래야 다음에 누가 곡선을 건드리면 하우스도르프가 잡는다.
2. **엔진을 옮겼으면 검사도 옮긴다** — 이 프로젝트에서 가장 자주 난 사고다.
   번호점 기대식·조각 이름·너치 목록·필수 제도선표·완성치수 식이 전부 따라와야 한다.
3. **겹친 그림을 남긴다** — 도면 위에 엔진 선을 얹은 SVG/PNG. 사람이 5초에 확인한다.
   정답지의 **표시점(MP·다트)** 도 함께 찍어라 — 도면 실측은 빈 원, 엔진은 채운 점,
   둘을 선으로 이으면 그 선의 길이가 곧 오차라 표를 안 봐도 읽힌다.
4. **산출물에 `undefined`/`NaN` 이 글자로 새지 않았는지 센다** (`references/checklist.md` G절).
   라벨은 K 값을 문자열로 붙여 만들어서, 상수 이름이 바뀌면 좌표는 멀쩡한데
   종이에 「어깨undefined」가 찍힌다. **그림도 산출물이다** — 겹침 SVG 까지 센다.
5. **검사를 넣었으면 오염을 주입해 증명한다** — 상수를 일부러 깨뜨려 검사가 잡는 것을
   본 뒤 되돌린다. 「넣었는데 헛도는 검사」가 이 프로젝트에서 여러 번 나왔다.

## 5. 도면과 원문이 충돌할 때

1. 원문이 **숫자로 못 박은 것**이 이긴다 (「1.5cm 내려」 「B/12」)
2. 원문이 침묵하면 **도면 실측**을 따른다
3. 도면끼리 충돌하면 **완성이미지**가 이긴다 (제도 과정 이미지는 모식도인 경우가 있다)
4. 봉제가 불가능해지면(시접 붕괴·짝 안 맞음) **봉제가 이긴다** — 실측은 tol 사유로 남긴다
5. 재단물이 바뀌는 선택은 **사용자에게 묻는다**

## 6. 이 스킬이 잡아낸 실제 사례

- 「밑단 안단선」으로 읽은 보라선이 사실 **밑단 완성선**이었다 → 조각이 9cm 길었다
- 앞목선을 **직선 V**로 그렸는데 도면은 볼록 곡선 (최대 1.9cm)
- MP 자리가 앞뒤 공통이었는데 도면은 **뒤=진동 · 앞=목선**
- 겨드랑다트가 진동선 위에 있었는데 도면은 **4cm 아래 옆선 위**
- 검산기가 0건인데 통짜 모드에 **어깨다트가 통째로 없었다** (4조각에만 그렸다)
