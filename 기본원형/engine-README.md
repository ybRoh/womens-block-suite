# engine.js 인수인계 노트 — 기본 무다트 원형 (문화식)

> 대상: 디자인팀(ui.*) · 출력팀(print.js) · QA팀. 기준 문서는 `SPEC.md` 이고 이 노트는 보충입니다.

## 1. 쓰는 법

```html
<script src="engine.js"></script>
<script>
  const m = NoDartEngine.measuresForSize('66호');   // '44호' | '55호' | '66호' | '77호'
  m.B = 89.0;                                       // 사용자가 고친 치수 (7개 중 아무거나)
  const draft = NoDartEngine.draftNoDart(m, { seam: {}, shoulderEase: 0.95 });
</script>
```

호수는 **44 · 55 · 66 · 77** 4단계입니다 (SPEC §11-3, 44호 = step −2).
목록은 `NoDartEngine.SIZES` 로 받으세요 — 하드코딩하지 마세요.

node 에서도 그대로 됩니다: `const E = require('./engine.js')`.
ES module import 없음, 외부 라이브러리 없음, 전역 오염은 `window.NoDartEngine` 하나뿐입니다.

### `draftNoDart(m, opt)` 의 opt

| 키 | 기본값 | 뜻 |
|---|---|---|
| `seam` | `0` | 시접. **숫자 = 전 부위 균일 · 객체 = 부위별** (아래 §시접 참조) · `0` 이면 `seamline === outline` |
| `shoulderEase` | `0.95` | 뒷어깨 이세분. 앞 어깨선 = 뒤 어깨선 − 이 값 |
| `hemStyle` | `'curve'` | 앞 밑단. `'curve'` = CF 38.8 → 옆선 38.5 전폭 완만곡선 (SPEC §9-1 확정) · `'spec'` = 구판 수평+하강 (호환용) |
| `frontSideEase` | `1.5` | 앞 옆선 여유분. DXF 대조 때만 `1.6` 을 씁니다 (SPEC §3.2 ※) |
| `capReduce` | `0` | 소매 대각선 감소량 0~1. **이세분을 줄이는 레버** (§3.4) |
| `sleeveType` | `'short'` | 소매 종류. `'cap'`(짧은소매) \| `'short'`(반소매). 목록은 `NoDartEngine.SLEEVE_TYPES` (SPEC §16) |
| `sleeveLen` | 종류·호수별 기본값 | 소매길이 미세조정. 주면 종류의 기본 길이를 덮어씁니다 |
| `includeSleeve` | `true` | `false` 면 소매 조각을 만들지 않습니다 |

### 반환값 (SPEC §8 계약 + 부가)

`pieces` 는 **3조각**입니다 — `back`(뒷판) · `front`(앞판) · `sleeve`(소매).
계약대로 `pieces / measures / size / meta` 가 있고, 여기에 아래를 **추가로** 얹었습니다.
쓰지 않아도 되지만 있으면 편합니다.

- `points.back / points.front` — 주요 제도점 (`SNP` `SP` `U` `BP` `BL` `WL` `sideX` `pitchX` …)
- `sleeve` — 소매 제도점 전부 (`capH` `halfB/F` `diagB/F` `bicepB/F` `markTopB/F` `markBotB/F`
  `footTopB` … 각 발점은 `{foot, t, dist}`) 와 곡선 길이 (`capLenBack/Front/Total`, `capEase`)
- `curves` — flatten 전의 베지어 세그먼트 배열. 곡선을 SVG `C` 명령으로 그리고 싶을 때.
  `NoDartEngine.util.sPath(draft.curves.backArm)` 로 바로 path 문자열이 나옵니다.
- `piece.edges` — `[{name, role, fold, seam, start, end}]` 변별 **`outline`** 인덱스 구간 + 실제 적용된 시접.

`outline` / `seamline` 은 **이미 flatten 된 조밀 폴리라인**입니다.
점 간격은 **호길이 기준 등간격 0.04cm** (t 등간격이 아닙니다 — 핸들이 짧은 구간에서
t 등간격은 간격이 몇 배로 벌어져 0.05cm 요구를 못 지킵니다).
출력팀은 베지어를 다시 해석할 필요 없이 `M x,y L x,y …Z` 로 이어 그리면 됩니다.
`outline` 은 마지막 점이 첫 점과 겹치지 않는 **암묵적 폐곡선**입니다 — 그릴 때 `Z` 를 붙이세요.

### 위치별 시접 (SPEC §11-1) — ⚠ 인덱스 규약이 바뀌었습니다

`opt.seam` 이 **숫자면 전 부위 균일**(기존 동작 그대로), **객체면 부위별**입니다.

```js
draftNoDart(m, { seam: 1.0 })                      // 균일 1.0 (골선만 0)
draftNoDart(m, { seam: {} })                       // 부위별 기본값
draftNoDart(m, { seam: { hem: 4.0, neck: 0.7 } })  // 일부만 바꾸기 (나머지는 기본값)
```

| role | 기본 | 해당 변 |
|---|---|---|
| `neck` | 1.0 | 뒷목둘레 · 앞목둘레 |
| `shoulder` | 1.0 | 어깨선 |
| `armhole` | 1.0 | 뒤암홀 · 앞암홀 · 앞/뒤 소매산 |
| `side` | 1.5 | 옆선 · 앞/뒤 밑선 |
| `hem` | 3.0 | 허리선(뒤) · 밑단(앞) |
| `sleeveHem` | 3.0 | 앞 밑단 · 밑단 중앙 · 뒤 밑단 (2026-08-18 에 2.5 → 3.0) |
| `fold` | **0 (강제)** | 뒤중심 · 앞중심 |

`fold` 는 사용자가 값을 줘도 무시하고 0 으로 강제합니다(원단을 접어 재단하므로).
`NoDartEngine.SEAM_DEFAULT` 로 기본값 표를 직접 읽을 수 있습니다.

**반환:**
- `piece.seamline` — **독립 폐곡선**. `outline` 과 인덱스 1:1 을 더 이상 보장하지 않습니다.
  (실제로는 모서리가 전부 마이터로 접히면 점 수가 같지만, 그것에 의존하지 마세요.)
- `piece.seamEdges` — `[{role, name, seam, start, end}]` **`seamline` 인덱스 기준** 변 구간.
- `piece.seamFoldEdges` — `[[start, end], …]` **`seamline` 인덱스 기준** 골선 구간.
  ⚠ 골선은 인덱스 0 을 감싸므로 보통 **두 구간**으로 쪼개집니다 (예: `[[0,0],[2132,3076]]`).
  하나라고 가정하지 말고 배열 전체를 순회하세요. `seamEdges` 도 같은 이유로 첫 항목과
  마지막 항목이 같은 변일 수 있습니다.
- `piece.foldEdges` — 예전대로 **`outline` 인덱스 기준** 골선 구간.
- `piece.seamByRole` — 실제 적용된 `{role: cm}`.
- `piece.edges[].seam` — 변별 실제 적용값.

**모서리 처리:**
- 두 변의 시접이 **같으면** 이등분선 마이터 — 균일 오프셋과 좌표가 완전히 동일합니다(하위호환).
- **다르면** 두 오프셋 직선의 교점. 예) 66호 앞판 옆선(1.5)↔밑단(3.0) → 모서리 (24.900, 41.500),
  옆선까지 1.5000 · 밑단까지 3.0000.
- 마이터 길이가 `max(두 시접) × 3` 을 넘으면 **bevel** (두 점을 직선으로 자름).
- 골선 접점은 **골선 위(x=0)를 유지한 채 이웃 변의 시접만큼 연장**합니다.
  예) 66호 뒷판 부위별 → 완성선 CB y 37.5 ~ −0.3 이 시접선 y 40.5 ~ −1.3, x 는 계속 0.
- 마지막에 **자기교차 루프 제거** 패스를 돌립니다 (아래 "타협한 부분" 참조).
- `seam = 0` 이면 `seamline` 은 `outline` 의 사본(좌표 완전 일치)입니다.

출력팀은 `seamline` / `seamEdges` / `seamFoldEdges` 를 그대로 쓰면 되고, 따로 오프셋을 걸 필요가 없습니다.

`internal[].label` 은 SPEC §8.1 대로 짧은 이름만 들어 있고 (`'등품선'`, `'BL'`, `'BP'`),
계산식은 `meta.formulaNotes` 에 `{id, label, formula, value, piece, anchor}` 로 분리돼 있습니다.
`piece` + `id` 로 `internal` 항목과 대응시키면 됩니다 (`piece:'both'` 인 항목은 대응 없음).

`notches[].angle` 은 도(°), 0° = +x, 시계방향 +, **조각 안쪽 방향**입니다. 눈금 길이는 UI/출력이 정하세요.

## 2. 제도 구조 요약

좌표계는 SPEC §1 그대로 — cm, x 는 중심선에서 옆선 쪽 +, y 는 상단 기준선에서 아래 +, 조각별 로컬 원점.

### 뒤판
```
BNP (0, −0.3) ─뒷목곡선─ 목옆점 ─어깨선─ SP ─암홀─ 겨드랑(B/4+1.9, B/4+0.6) ─옆선─ WL ─허리선─ CB
```
- 목너비 사각 모서리 `(B/12, −3.5)` → 고정치수선 위 `(23.5, 3.1)` 을 잇는 직선이 어깨선 (SPEC §3.3)
- **목옆점은 그 모서리가 아니라, 어깨선을 따라 바깥으로 1.0 나간 점**입니다 (도면의 `1(⅜)`).
  뒷목 곡선과 어깨 솔기가 둘 다 이 점에서 만나요. 원본 DXF도 그렇게 그려져 있습니다.
- SP = 어깨선 ∩ `x = 어깨너비/2 + 0.6`

### 앞판
```
FNP (0, B/12+0.3) ─앞목곡선─ 목옆점(B/12, −0.6) ─어깨선─ SP ─암홀─ 겨드랑(B/4+1.5, B/4+1.6)
   ─옆선─ 옆선밑단(등길이+1.0) ─밑단─ CF밑단(0, 등길이+1.3) ─앞중심─ FNP
```
- 앞판 상단 기준선은 뒤판보다 1.0 위 → BL 이 `B/4+1.6`, 옆선 밑단이 `등길이+1.0`.
  덕분에 앞뒤 옆선 길이가 정확히 같아집니다 (`등길이 − (B/4+0.6)`).
- 어깨선 = 목옆점 → `(23.5, 5.4)`, SP 는 그 위에서 `뒤 어깨선 − 이세분` 거리
- BP = `(유폭/2, 유장 − 0.6)` — CF 상단점(y=−0.6)에서 수직으로 유장만큼

## 3. 곡선 — Freesewing(Brian) 골격 + DXF 캘리브레이션

`draft-bunka-fs.js` 의 `V` `bez` `bezLen` `through` `sPath` `LN` `lineSegs` `sampleSegs`
`offsetLoop` 을 그대로 이식했습니다 (`NoDartEngine.util` 로도 열어 뒀습니다).

곡선 앵커 구조는 Freesewing 그대로입니다.

| 곡선 | 앵커 | 끝점 접선 |
|---|---|---|
| 뒷목선 | BNP → 중간점 → 목옆점 (2 큐빅) | CB 수평 · 목옆점 어깨선 ⟂ |
| 앞목선 | FNP → **목 사각 대각선 2/3 점** → 목옆점 (2 큐빅) | CF 수평 · 목옆점 어깨선 ⟂ |
| 암홀 | 겨드랑 → hollow → 품점 → SP (3 큐빅) | 겨드랑 수평 · SP 어깨선 ⟂ |
| 앞 밑단 | CF (0, 등길이+1.3) → 옆선 (0, 등길이+1.0) (1 큐빅) | **양끝 수평** (CF 골선 ⟂ · 옆선 ⟂) |
| 소매산 | 정점 → 상단 볼록점 → 하단 오목점 → 소매폭 끝 (3 큐빅, 앞뒤 각각) | 정점 수평 |
| 소매 밑단 | 2등분점 → 끝점 (1 큐빅, 앞뒤 각각) | 2등분점 수평 |

앞목 곡선이 지나는 **대각선 2/3 점은 추측이 아닙니다** — 66호 DXF 의 원호/스플라인 접합점
`(4.8667, 5.0666)` 과 `(B/12, B/12+0.3) × 2/3 = (4.8667, 5.0667)` 이 소수 4자리까지 일치합니다.

핸들 길이와 중간 앵커 위치는 `engine.js` 의 `CAL` 객체에 있습니다. **전부 무차원 비율**
(스팬 대비 %, 현에서의 회전각)이라 호수가 바뀌어도 곡선 모양이 자기유사하게 유지됩니다.
66호 DXF 폴리라인에 대한 최대편차를 최소화하도록 적합한 값이며, 다시 맞추려면
`engine-verify.js` 로 편차를 확인하면서 조정하세요. 절대 cm 값으로 바꾸면 그레이딩이 깨집니다.

## 3-S. 소매 (SPEC §3.4 + §16)

### 소매 종류 — 짧은소매 · 반소매 2종뿐입니다

| key | 이름 | 소매길이 66호 | 호수당 | 소매부리 |
|---|---|---|---|---|
| `cap` | 짧은소매 | 19.0 | +0.4 | 소매폭 − 3.0 |
| `short` | **반소매 (기본)** | 25.0 | +0.5 | 소매폭 − 3.0 |

두 종류는 **소매길이만 다릅니다.** 제도법(소매산·대각선·밑단 들임 1.5·2등분점 0.5 하강·
밑선 직선)은 §3.4 그대로 공유합니다. 소매산 곡선과 이세분은 AH 로만 결정되므로
**종류를 바꿔도 완전히 동일**합니다 (검증 `[T-3]` 에서 좌표 최대차 0.0e+0 확인).

`sleeveType` 을 생략하거나 모르는 값을 주면 `'short'` 로 떨어지고, 그 좌표는
기존 구현과 완전히 일치합니다 (`25.0 + 0.5·step` ≡ 기존 `25.0 + (B−87.6)/12`).

> ### ⚠ 7부소매·긴소매는 일부러 만들지 않았습니다
> **긴소매는 소매길이만 늘린 반소매가 아닙니다.** 팔꿈치 처리·뒤팔꿈치 여유·소매부리 트임·
> 소매산 높이가 모두 다른 **별도 제도법**입니다. 원본 `반소매원형.dxf` 의 제도법
> (`AH/4+2` · `AH − capReduce` · 들임 1.5 · 2등분점 0.5)은 반소매 계열 전용입니다.
>
> 사용자가 긴소매 제도법 도면과 DXF 를 제공하면 그때 별도로 구현합니다.
> `SLEEVE_TYPE` 표에 `threequarter`/`long` 을 **추측으로 추가하지 마세요.**
> 검증 `[T-6]` 이 종류가 2개인지, `id:'elbow'` 가 없는지, 소매부리에 표준치수 출처가
> 섞여 들어오지 않았는지를 감시합니다.

### 제도법 (§3.4)

로컬 원점 = **소매산 정점**. x 오른쪽 +(앞) / 왼쪽 −(뒤), y 아래 +.
`AH`·`뒤AH`·`앞AH` 는 몸판 draft 에서 자동 산출됩니다 — 사용자 입력이 아닙니다.

```
소매산 높이 = AH/4 + 2
대각선     = 뒤AH − capReduce  /  앞AH − capReduce
반폭       = √(대각선² − 소매산²)
밑단 들임  = 좌우 각 1.5,  밑단 2등분점에서 끝까지 0.5 하강
```

소매산 곡선은 **대각선 기준 수직 오프셋** 방식입니다.
정점에서 수평으로 `AH/8` 인 상단 마크, 소매폭 끝에서 안쪽으로 `AH/12+0.6`(뒤)·`AH/8`(앞) 인
하단 마크를 잡고, 각 마크에서 대각선에 수선을 내려 발점을 구한 뒤, **발점↔마크 사이
`capBulge` 비율 지점**을 지나도록 곡선을 그립니다.

`capBulge` 는 `0.45` 입니다. 원본 DXF 는 정확히 `0.5`(수선의 이등분점)인데,
교재식 `AH/8` 마크를 이 몸판의 AH 에 적용하면 수선이 DXF 보다 길어져
(66호 3.42/2.63/3.48/3.48 vs DXF 3.15/2.45/2.96/2.96) 0.5 로는 오프셋이 1.71~1.74 로 과해집니다.
0.45 를 쓰면 오프셋이 1.54/1.18/1.57/1.57 이 되어 **SPEC §3.4 표(1.50/1.23/1.48/1.49)에
±0.09 이내로 더 가깝고**, 이세분도 전 호수 PASS 대역에 들어옵니다.
검증 출력 `[S-5]` 에 이 비교가 찍힙니다.

**이세분은 `capReduce` 로 조절합니다.** 기본 0 에서 44~88호 = 1.79 / 1.90 / 2.00 / 2.11 / 2.21 cm.
`capReduce` 를 0.25 올릴 때마다 약 0.44 cm 줄어듭니다 (66호 기준 0→2.00, 0.5→1.12, 1.0→0.25).

**앞뒤 밑선 길이가 정확히 같습니다.** 좌우 소매폭이 다르지만(66호 뒤 19.394 / 앞 18.882)
들임을 좌우 **같은 값**으로 주므로 밑선의 가로·세로 변화량이 양쪽 동일해집니다

`cutCount: 2`, 식서 = 중심선. 너치 5개(정점 · 앞뒤 합인 · 앞뒤 밑단 2등분점).

## 5. 쟁점 이력 — (1)(2)(3) 은 SPEC §9 로 해결, (6) 만 확인 필요

### (1) 앞 밑단 형태 — **해결됨 (SPEC §9-1)**
`lines[44]`(y=38.5 수평)는 `lines[2]`(뒤 허리선)를 앞판 위로 이어 그린 **정렬 안내선**이고,
실제 밑단은 `curves[2]` 의 전폭 완만곡선이라는 개발팀 판단이 채택됐습니다.
기본값 `hemStyle:'curve'`. 구판 `'spec'` 은 호환용으로만 남겨 뒀습니다
(편차 비교는 검증 출력 `[1-D]`).

추가로 밑단 곡선의 **옆선 쪽 끝 접선을 정확히 수평으로 바꿨습니다.** 이전 값(−3.29°)은
DXF 형상에는 0.005cm 로 더 잘 맞았지만 옆선(수직)과 직각이 아니어서, 앞뒤를 옆선에서 붙였을 때
뒤 허리선과 3.3° 꺾였습니다. 수평으로 고정해도 DXF 대비 편차는 0.0316cm 로 허용치 안입니다.

### (2) 어깨 안내선의 `+0.6` 과 이세분 `0.95` — **해결됨 (SPEC §9-2)**
DXF 는 `20.35 = 39.5/2 + 0.6` 이라 `+0.6` 은 이세분과 별개 상수입니다.
`K.shTipExt = 0.6` (전 호수 상수) 과 `opt.shoulderEase` 를 분리한 개발팀 안이 채택됐습니다.

### (3) 뒤 어깨선 길이 정의 — **해결됨 (SPEC §9-3)**
뒷목 곡선이 목옆점이 아니라 어깨선 1.0 연장점에서 끝나므로 실제 솔기는 뒤 13.09 / 앞 13.14.
`measures.shoulderBackSeam` / `shoulderFrontSeam` 을 내보냅니다 — 봉제 지시는 이쪽을 보세요.
`shoulderBack`(14.09) 은 구성선 기준값입니다.

### (4) 실효 접선 — 어깨점·목옆점에서는 「수직」이 형식적입니다
`engine-verify.js` 는 두 가지로 잽니다.
- **해석적 접선** (베지어 도함수) — 어깨선 수직 조건을 0.12° 이내로 만족합니다. §5-7 PASS.
- **실효 접선** (끝점에서 0.3cm 현) — 어깨점에서 뒤 8.4° · 앞 2.0° 어긋납니다.

이건 버그가 아니라 **원본 도면이 그렇게 생겼기 때문**입니다. 같은 방식으로 잰 DXF 원본이
어깨점에서 뒤 9.0° · 앞 3.7°, 목옆점에서 뒤 6.0° · 앞 3.0° 입니다. 즉 원본 자체가
어깨선에 정확히 수직으로 만나지 않습니다. 엔진은 끝점에서만 짧게 수직으로 출발한 뒤
바로 원본 궤적에 올라탑니다 (`CAL.*.h5` 가 작은 이유). 0.05cm 대조를 통과하면서
「어깨선 수직」 형식 요건도 만족시키는 유일한 방법이었습니다.

**골선(CB·CF)·옆선에 대한 수직은 형식이 아니라 실질입니다** — 실효 접선으로도
0.06~0.6° 이내라 앞뒤를 붙였을 때 목·겨드랑에 꺾임이 없습니다. 이쪽이 봉제상 중요한 조건입니다.

### (5) 그레이딩 부작용 2건 — **해결됨 (SPEC §9-5: 교재 계산식 그대로 유지)**
어깨 솔기 14.14 → 14.09 → 14.05, 옆선 16.0 → 15.0 → 14.0 으로 큰 호수에서 줄어듭니다.

### (6) 위치별 시접에서 타협한 부분 — 자기교차 루프 제거
변별 오프셋 후 **자기교차 루프 제거** 패스를 돌립니다. 이게 필요한 이유는 실제로 겹치는
경우가 있기 때문입니다 — **44호 뒷판 암홀**은 등품/2 = 17.2, 옆선 = 20.8 로 폭이 3.6cm 뿐이라
곡률반경이 작고, 1.5cm 를 바깥으로 밀면 시접선이 자기 자신을 파고듭니다
(구버전 균일 오프셋은 이 겹침을 그대로 두고 있었습니다 — 검증 `[11-1c]` 에 찍힙니다).

- 제거 방식: 교차하는 두 선분 사이의 **짧은 쪽 루프를 교점 하나로 대체**. 최대 60회 반복.
- 그 결과 44호 뒷판만 점 수가 줄어듭니다 (seam 1.0 → 2915→2909, 1.5 → 2915→2895).
  **44호 뒷판 균일 시접에서는 구버전과 좌표가 다릅니다.** 겹침을 없앤 쪽이 맞다고 판단했습니다.
- **한계**: 루프가 3겹 이상 중첩되면 "짧은 쪽" 판정이 어긋날 수 있습니다(이론상).
  실측으로는 4개 호수 × 3조각 × 8가지 시접 조합(`{}`, `{hem:8}`, `{hem:6,side:4,armhole:2}`,
  전부 0.5, 균일 1.0/1.5/2.0, 0)에서 **전부 자기교차 0** 을 확인했습니다.
- 오목 모서리의 정확한 "오프셋 envelope"(원호로 잇기)은 구현하지 않았습니다. 마이터/bevel +
  루프 제거로 처리합니다. 재단선 용도로는 충분하지만, 수학적으로 엄밀한 Minkowski 오프셋은 아닙니다.
